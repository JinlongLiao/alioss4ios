# 项目设计与迁移说明

| 边界 | 实现 |
| --- | --- |
| 界面 | `AliOSSApp` 统一组织文件与设置，窄屏使用紧凑分栏，宽屏保留侧栏 |
| 配置 | `StorageProfile` 描述连接，`ProfileVault` 保存凭据，`ProfileBackup` 处理 ALOS 交换格式 |
| 存储 | `ObjectStorage` 和 `MultipartStorage` 约束共享行为，OSS 和 S3 使用各自的 SDK |
| 目录与文件操作 | `DirectoryCache` 按账号和路径缓存目录，`ObjectMutations` 处理同 Bucket 操作 |
| 上传 | `UploadQueue` 串行运行任务，将服务端确认的分片记录原子写入本地 |
| 预览 | 小文档使用有界读取，音视频交给 AVPlayer，文件预览使用 Quick Look |
| 配色与语言 | 主色、底色和卡片圆角参考 Android，同一主题独立支持明暗模式 |

## 状态与失败边界

目录请求绑定账号、Bucket 和目录。使用请求代次保护加载结果，避免切换后显示旧目录。写入结果通过缓存失效和刷新反馈。

递归操作先分页采集并校验对象范围。移动逐对象复制后删除源对象，失败时保留已完成数量和当前阶段。OSS 的删除先核对 ETag 再执行 DeleteObject，两个请求间仍存在并发窗口。S3 使用服务端条件请求。递归操作最多处理 10000 项。

上传历史保存源文件书签、连接路由、上传 ID 和已确认分片，凭据从钥匙串读取。与原路由或文件属性不符时提示用户。iOS 使用系统后台会话发送大文件分片和 OSS/S3 小文件。系统重新启动应用后，回调按原任务和上传会话匹配；系统挂起期间的交付仍待实测。

## 平台差异

两个平台使用同一套存储与业务源码。Mac 使用原生保存面板和独立窗口，iOS/iPadOS 使用系统文档选择器与模拟器或真机签名。Apple 预览能力取决于当前系统支持的文档与媒体格式。
